## 2. Experimental Integrity Audit

**Run completeness, with corrected arithmetic (completion-pass fix).** The first pass of this report wrote the Track-B count as "`... × 150 learners × 3 conditions`", which double-counts: reading `src/research/phase8/pipeline/pilot.ts` lines ~161-230 directly, the actual loop nesting is `familyConfig → world (1-5) → slice (3) → learner (0-49, i.e. 50 distinct learner ids "pilot-000".."pilot-049") → conditionId ∈ {C0,C2,C3}`. So there are only **50 distinct learner identities**, each run once per slice (3 slices) per world (5 worlds) — "150" is `50 learners × 3 slices` (150 *sessions*, not 150 *learners*) per world per condition, and that 3-slice factor must not be multiplied in twice. The correct equation is:

`6 Track-B family-configs × 5 worlds × 3 slices × 50 learners × 3 conditions (C0,C2,C3) = 13,500 Track-B sessions`

plus `4 Track-A family-configs × 5 worlds × 3 slices = 60 Track-A contexts` (each context internally evaluates `calLearners=100` + `testLearners=100` simulated learners against all 7 Tier-1 estimators, but `pilot.ts` increments `totalRuns` once per *context*, not per learner — confirmed by reading the `totalRuns++` placement in the Track-A loop, which sits outside any per-learner loop). `60 + 13,500 = 13,560`, matching both reports' `totalRuns` field exactly. The pooled `n=750` used throughout Parts 5-7 below for each (family, condition) QTM/attainment cell is `50 learners × 3 slices × 5 worlds = 750` — this number was already correct in the first pass; only the single combined equation text above it was wrong, and is fixed here.

**K(T) — the one correct definition, resolved from source (completion-pass fix — this corrects an inconsistency between how this document and its companion previously described K(T)).** Traced `kT` to its exact point of computation in `src/research/phase8/trackB/runTrackB.ts`:
```ts
const endTruthT = slice.targetConceptIds.map((c) => simulatedLearner.truth(c));
const kT = mean(endTruthT.map((t) => t.m));
```
`simulatedLearner.truth(c)` calls the family-specific `s{1,2,3,4}Truth(...)` function (`src/research/phase8/simulator/{s1,s2,s3,s4}.ts`), which reads the **simulator's own hidden ground-truth state** — never the estimator's `ConceptMasteryState.mastery`. **K(T) is therefore ground truth, not an estimator's belief, in every condition, including C0.** Concretely: `t.m` is continuous (`m = sigma(theta)`, a logistic transform of the learner's latent trait) for S1/S3, and binary (`m = L ∈ {0,1}`) for S2/S4 (see Part 13's full simulator-equation audit). `kT` is the **mean of `t.m` across every target concept in the slice**, read once at the end of the session (whatever step it ends on — budget=60 for every session in this pilot, since `completionCheck` is deliberately left `undefined`, i.e. an intention-to-treat measurement, never an early "mastery achieved" stop). This is a *continuous* aggregate measure, distinct from `itemsToCriterion`'s *binary, joint* event (every target concept's `t.mastered` flag true *simultaneously*) — both are read from the same underlying truth stream, so they are **consistent constructs** (both ground-truth-based), differing only in continuous-mean-of-many vs. binary-joint-event-over-the-same-many. They are not measuring the same thing, and were never claimed to be, but they are not in conflict either.

**How C0 (null estimator) still gets a meaningful `kT`:** `kT` never reads anything from the condition's estimator or selection policy — it is purely a property of the simulated learner's accumulated hidden state at the end of the session, which the *selector* (C0's fixed, performance-independent sequence vs. C1/C2/C3's adaptive choices) shapes only indirectly, by determining *which* items the learner actually answers (and therefore which concepts accrue learning opportunities). C0's null estimator plays no role in computing `kT` at all; it only means C0 has no mastery *belief* to report, which is irrelevant to this ground-truth measurement.

**Does the S4-GF reversal survive this corrected definition? Yes — re-confirmed directly.** Both `kT` and `itemsToCriterion` read from the identical `simulatedLearner.truth()` stream; neither is a confusion between estimated and true mastery, and neither pass of this document ever actually computed one from the estimator. The reversal reported in Part 5 (C2's continuous mean K(T) exceeds C0's in S4-GF, while C2's binary joint-attainment rate is far below C0's in the same family, Part 7) compares two different ground-truth constructs on the *same* underlying hidden state — a legitimate, intended contrast (mean-per-concept mastery vs. probability-of-joint-mastery), not an artifact of measuring two different things under one name. This check is treated as the single most important correction in this pass, per the coordinator's instruction, and it confirms the earlier finding stands.

## 4. Step 4 — C2 vs C3 prerequisite ablation (recovered, all families)

**What the flag actually controls**, verified directly in `src/tutoring/selection/adaptive/targeting.ts:241-293`: `prerequisiteAware: false` (C3) disables **both** diagnostic backtracking (`diagnostic_probe`) and ordinary prerequisite remediation (`prerequisite_backtrack`) — every struggling concept is remediated **on itself only**; `prerequisiteAware: true` (C2) additionally enables both of those cross-concept paths. Difficulty selection, target-concept progression logic, and fallback selection are **not** touched by this flag (confirmed by reading the full function — the flag only gates the two `if (config.prerequisiteAware) { … }` branches at lines 242 and the paired `else` path at 291). So this ablation is a clean isolation of "may the selector ever target a prerequisite concept," not a bundle of several unrelated mechanism changes — Step 4's "if multiple mechanisms change, identify as bundle" caveat does **not** apply here; it is a single, well-isolated mechanism.

## 8. Step 8 — Uncertainty and statistical limitations

**Unit of inference.** Every t-statistic in this report (Parts 4–7) was computed on **5 world-level paired means**, never on the 150 (or 750) pooled learner-level observations within a world. This repository's own 8C-Pilot code makes the same choice (`sampleVariance`/`requiredW` in `pilot.ts` operate on the 5-element `*ByWorld` arrays) — this report's recomputation matches that unit of inference exactly, and nowhere in this document are the 750 pooled trials per family/condition treated as 750 independent inferential units (Part 4 restriction #6 is respected throughout).

**n=5 means every reported t/p-style statistic is fragile.** A 5-point sample barely supports a normality check at all; none of the comparisons above should be read as more than exploratory signal.

**Exact p-values and 95% CIs — computed this pass (completion-pass fix of the first pass's "no p-values computed" gap).** Because every single comparison in this entire deliverable uses exactly 5 worlds (df = n−1 = 4, with zero exception), the Student-t CDF for df=4 has a closed form, derived and verified in `verification_scripts/compute_pvalues.py`:

```
F(t; df=4) = 0.5 + (u/4)(3 − u²),   u = t / sqrt(4 + t²)
```
(derived by direct integration of the df=4 t-density; verified against this repo's own `T_CRIT_975_DF4 = 2.776` constant — `compute_pvalues.py`'s self-check computes `two_sided_p_df4(2.776) = 0.05002`, i.e. recovers the 0.05 two-sided threshold that constant was chosen to represent, confirming the closed form is correct). This required no `scipy` dependency and no numerical integration — it is an exact, not approximate, calculation for this specific, fixed df.

For every paired world-level comparison: mean paired difference, SD, SE = SD/√5, t = mean/SE, the exact two-sided p-value via the formula above, and a 95% CI = mean ± `T_CRIT_975_DF4` × SE. **70 total comparisons** are now computed this way (up from the 28 "exceeds-threshold-only" flags in the first pass): the original 12 K(T) + 16 Track-A contrasts, plus 18 new C1-vs-{C0,C2,C3} K(T) contrasts (Part 3) and 24 new det-B-vs-{det-A,BKT-fit} Track-A contrasts (Part 6). Full results: `appendix_tables/table_PVALUES_all_paired_comparisons.csv` (70 rows) and reproduced inline in Parts 3, 5, and 6 above. **No manuscript-reported p-value was found to cross-check these against** — the manuscript itself does not appear to state exact p-values for these specific contrasts anywhere this audit located; this is noted as a gap in the manuscript's own reporting, not a discrepancy this report could resolve against it.

**Multiple comparisons.** With 70 total unadjusted comparisons now computed (vs. 28 in the first pass), the multiple-comparisons caveat is strengthened, not relaxed. No Holm or other multiple-comparison correction is applied anywhere in this document — every p-value above is reported as **exploratory and unadjusted**, consistent with the task's instruction not to retroactively claim corrections were prespecified. As a separate, explicitly-labeled sensitivity check only (not a replacement for the unadjusted values above): a Holm-Bonferroni correction across all 70 comparisons would require the smallest p-value to beat 0.05/70 ≈ 0.00071 to survive at the family-wise 0.05 level after the full step-down procedure; by inspection of `table_PVALUES_all_paired_comparisons.csv`, roughly half of the 70 raw p-values are below 0.001 and would likely survive a full Holm procedure, while the borderline cases (e.g. S4-GF C2-vs-C3 at p=0.164, several S3 Track-A contrasts at p>0.1, several C1-vs-C2 K(T) contrasts at p=0.03-0.08) would not. This is reported as a rough sensitivity observation, not a formally executed Holm procedure (which requires the full ordered p-value list and step-down comparison against a sequence of thresholds, not performed here), and should not be read as a prespecified correction.

**Protocol-history endpoint hierarchy, preserved as-is, not silently promoted.** Per `protocol/phase8-protocol-v2.md` deliverable B8, the frozen hierarchy is: log loss (Track A principal), latent MAE (Track A accuracy endpoint), K(T) (Track B primary), with Brier and censored-QTM as secondary/exploratory. `protocol/PROPOSED-AMENDMENT-A2-metric-reconciliation.md` (dated 2026-11-05, in `protocol/`, **read but not modified** by this audit) proposes promoting Brier/QTM and introducing RMSE — it remains, per its own filename and status line, an **unapproved, post hoc amendment**; this report cites its Brier/RMSE/QTM numbers as the already-computed secondary/exploratory metrics the amendment defines, never as confirmatory primary results, and does not treat the amendment as adopted.

## 13. Full S1-S4 Simulator and Mastery Specifications (completion pass — read line-by-line from source, not taken from naming)

All four families share the same RNG mechanism (`src/research/phase8/rng/derive.ts`): every draw is `derive(masterSeed, key)` → SHA-256 → a uniform or (via Box-Muller) normal variate, where `key` is a structured tuple over `(track, familyGroup, world, slice, split, learner, stream, concept, index)`. Shared helper functions and constants live in `src/research/phase8/simulator/shared.ts`.

**Shared parameters** (`protocol/phase8-protocol-v2.md`'s `simulator-config-v2.json`, confirmed live-loaded by `src/research/phase8/config/load.ts`): `delta=0.6` (item-difficulty slope), `sigmaB=0.5` (item-noise SD), `muSd=1.0` (learner-ability SD), `uSd=0.6` (learner×concept-offset SD), `cSd=0.5` (concept-easiness SD), `thetaOffset=-1.0`, `gammaSd=0.05` (guess-rate learner-offset SD), `guessClip=[0.05,0.45]`, `slip∈[0.02,0.12]` (continuous-family slip range), `probClip=[0.01,0.99]`, **`masteredM=0.8`** (the single shared continuous-mastery threshold — same value, same config field, used by both S1 and S3; there is only one `masteredM` in the schema, so "is it the same threshold in both families" is answered by construction: it cannot differ, both read `cfg.shared.masteredM`), reference item `{options:4, level:3}`.

### S1 — Stationary logistic learners (`simulator/s1.ts`)
- **Initial hidden state:** `theta_lk(0) = mu_l + u_lk + c_k + thetaOffset`, where `mu_l ~ N(0, muSd²)` (learner ability, drawn once per learner), `u_lk ~ N(0, uSd²)` (learner×concept offset), `c_k ~ N(0, cSd²)` (concept easiness, shared across all learners in a world). Drawn lazily, memoized per concept (`s1Theta`, lines 46-55).
- **Transition:** **none.** `s1Learn` (lines 86-108) only advances the opportunity counter `opp`; `theta` is returned unchanged. Code comment, verbatim: "S1 has no transition: learn() only advances opportunity counts, latent state is unchanged."
- **Response probability:** `pCorrect = clip(g + (1−g−s)·σ(θ_Q − b), probClip)` (`s1Respond`, line 81) where `g` = learner guess rate (`clip(1/nOptions + γ_l, guessClip)`), `s` = learner slip rate (`U(slip)`), `b` = item difficulty in logits (`delta·(level−3) + itemNoise`), `θ_Q` = concept-weighted mean of `θ_lk` over the item's concepts, `σ` = logistic sigmoid.
- **Truth/mastery:** `pStar = clip(g_ref + (1−g_ref−s)·σ(θ), probClip)` (reference-item, level-3, 4-option correctness probability); **`m = σ(θ)`** (continuous, 0-1); **`mastered = m ≥ masteredM (0.8)`** (`s1Truth`, line 120).
- **Can a mastered concept become unmastered?** **No.** `theta` never changes after initialization (no transition at all) — `m` is constant for the entire session, so once `m ≥ 0.8` it stays there forever (and if `m < 0.8` at init, it stays there forever too — S1 is the designed "policy-invariant" sanity family, Part 5).
- **Concept-dependence:** `theta`, hence `m`/`mastered`, is per-concept and independent across concepts (no cross-concept transfer in S1).

### S2 — BKT-generative learners (`simulator/s2.ts`) — "standard 4-parameter BKT as ground truth"
- **Initial hidden state:** `L_lk(0) ∈ {0,1}`, `P(L=1) = pL0_k` (drawn once per world per concept, `pL0_k ~ U(S2.pL0 range)` — world-level, shared by every learner in that world; the Bernoulli draw itself, `u < pL0`, is learner-specific).
- **Transition:** on each *counted* opportunity (a `U(w̃_qk)` coin flip, `opportunityCounted`) touching a concept with `L=0`: `L → 1` with probability `T_k` (drawn per-world, `T_k ~ U(S2.T range)`). **No forgetting** — `L=1` never reverts to `0` (code comment, verbatim, `s2Learn` line 111: "No forgetting"). `o_k` (opportunity count) increments on every presentation unconditionally, regardless of whether the coin flip succeeds.
- **Response probability:** `pCorrect = L·(1−S_k) + (1−L)·G_k` — standard BKT emission, `G_k ~ U(S2.G range)` (guess), `S_k ~ U(S2.S range)` (slip), both world-level per-concept.
- **Truth/mastery:** `pStar = L·(1−S_k) + (1−L)·G_k` (same as response probability — S2's "reference item" IS the ordinary item, no separate reference-item correction); **`m = L`** (already binary); **`mastered = (L === 1)`**.
- **Can a mastered concept become unmastered?** **No** — explicitly, by the "no forgetting" design.
- **Concept-dependence:** each concept has its own independently-drawn `(pL0,T,G,S)` and independent `L`; multi-concept items pick one "responding concept" per presentation (`pickMixtureConcept`, weighted by normalized concept weights) rather than updating all weighted concepts simultaneously.

### S3 — Practice-driven continuous learners (`simulator/s3.ts`) — Additive Factors Model as generator
- **Initial hidden state:** `theta0_lk = mu_l + u_lk + c_k + thetaOffset` — identical functional form to S1's fixed `theta`, but here it is only the *starting point* for growth.
- **Transition:** `theta_lk(t) = theta0_lk + growth_lk(t)`, where `growth` accumulates `+η_lk` on every *counted* opportunity (same `opportunityCounted` coin-flip mechanism as S2): `η_lk = η_k · exp(ν_l)`, `η_k ~ U(S3.eta range)` (world-level per-concept base learning rate), `ν_l ~ N(0, nuSd²)` (learner-level log-multiplier, `nuSd=0.3`). Code comment, verbatim (`s3Learn`, line 131): "each counted opportunity adds eta_lk to theta, independent of correctness/difficulty." **Growth is strictly non-negative and monotonically accumulating** — `theta` (and therefore `m`) never decreases.
- **Response probability:** identical functional form to S1 — `pCorrect = clip(g + (1−g−s)·σ(θ_Q(t) − b), probClip)`, using the *current* (grown) `theta`.
- **Truth/mastery:** `pStar = clip(g_ref + (1−g_ref−s)·σ(θ), probClip)`; **`m = σ(θ)`** (continuous); **`mastered = m ≥ masteredM (0.8)`** — the identical shared threshold S1 uses, confirmed by both reading `cfg.shared.masteredM` with no family-specific override anywhere in `s3.ts`.
- **Can a mastered concept become unmastered?** **No** — `theta` is monotonically non-decreasing (growth only ever adds a positive `η_lk`), so `m=σ(theta)` is also monotonically non-decreasing; once `m≥0.8`, it can never fall back below.
- **Concept-dependence:** per-concept `theta0`/`growth`, independently accumulated; no cross-concept transfer.

### S4 — Prerequisite-gated binary learners (`simulator/s4.ts` + `simulator/trueGraph.ts`) — the only family with a true graph G\* distinct from the tutor-visible curriculum graph G
- **The true graph G\*** (`trueGraph.ts`, `buildTrueGraph`): built once per world, shared by all 4 S4 cells (S4-ref/S4-GF/S4-N/S4-GW all key off the shared `familyGroup: "S4"`). For every curriculum prerequisite edge `(prereq → dependent)`, a per-edge draw `u_keep ~ U(0,1)` keeps that exact edge in G\* if `u_keep < φ`; otherwise the edge is **dropped** and a **uniformly random replacement edge** `(i', j')` (`i'` earlier than `j'` in the fixed topological order) is added instead, so the *total* edge count is preserved even as *which* edges exist is scrambled. **`φ=1.0` ⟺ G\*≡G exactly** (zero edges ever dropped); **`φ=0.0` ⟺ every single edge is replaced by an unrelated random edge.** `isAcyclic(graph)` is checked structurally (every edge respects the fixed topological order by construction).
- **Initial hidden state:** `L_lk(0) ∈ {0,1}`, `P(L=1) = κ(0,k)·π_k`, where `π_k ~ U(S4.piTarget range)` if `k` is a target concept for that slice, else `U(S4.piOther range)` (target concepts start *less* likely to be already mastered than external/prerequisite concepts — `piTarget=[0.05,0.25]` vs `piOther=[0.40,0.80]`), and `κ(t,k) = 1` if every G\*-parent of `k` already has `L=1`, else `κ(t,k) = λ` (the **gating factor** — this is exactly what `λ` controls). Concepts are initialized in G\*'s topological order so every parent's state is already set before its children are initialized (`s4InitializeAll`).
- **Transition:** on each counted opportunity with `L=0`: `L → 1` with probability `κ(t,k)·τ_k`, `τ_k ~ U(S4.tau range)` (world-level per-concept base transition rate), `κ(t,k)` recomputed from the *current* state of G\*-parents at that moment. **No forgetting** (explicit code comment, `s4Learn` line 155: "No forgetting"). **`λ` is literally the gating strength**: `λ=1.0` makes `κ≡1` always (gating has zero effect — prerequisites are irrelevant to transition probability, hence "S4-N" = "No gating"); `λ→0` makes transition near-impossible until every true prerequisite is mastered (strong gating).
- **Response probability:** `pCorrect = L·(1−slip(S_k,level)) + (1−L)·guess(G_k,level)`, with level-dependent slip/guess: `slip = S_k·exp(ζ(level−3))`, `guess = G_k·exp(−ζ(level−3))`, `ζ=0.25` (harder items slip more / guess less, scaled exponentially around the reference level 3).
- **Truth/mastery:** `pStar = L·(1−S_k) + (1−L)·G_k` (at reference level 3, where the ζ-exponent is 0); **`m = L`** (binary); **`mastered = (L===1)`**.
- **Can a mastered concept become unmastered?** **No** — explicit "no forgetting" design, same as S2.
- **The four S4 cells, fully defined, from the config table (`protocol/phase8-protocol-v2.md`'s `simulator-config-v2.json`, `S4.cells`) — not from their names:**

| Cell | λ (gating strength) | φ (graph fidelity) | What this means |
|---|---|---|---|
| S4-ref | 0.30 | 1.0 | Moderate gating; G\*≡G (faithful graph). The Track-A reference configuration. |
| **S4-GF** | **0.05** | **1.0** | **Strong gating; G\*≡G (faithful graph).** "GF" = Gated, Faithful-graph. **No graph misalignment exists in this cell** (Part 9, hypothesis 5). |
| **S4-N** | **1.0** | **1.0** | **No gating** (κ≡1 always — prerequisite mastery state has zero effect on transition probability); G\*≡G (irrelevant here since gating is off anyway). "N" = No gating. |
| **S4-GW** | **0.05** | **0.0** | **Strong gating; G\* is a fully scrambled, wrong graph** (every curriculum edge replaced by a random one). "GW" = Gated, Wrong-graph. The only cell where graph misalignment is actually present. |

This table is derived entirely from the `{lambda, phi}` values actually read by `pilot.ts`/`runTrackA.ts` (`cfg.simulator.value.S4.cells[cellName].{lambda,phi}`) — not inferred from the "GF"/"N"/"GW" naming, which this pass independently confirms the naming does accurately describe once the mechanism is read.

### Summary answers to the completion-pass's specific questions
- **Exact threshold:** `masteredM = 0.8`, one single shared config value, used identically by S1 and S3 (the only two continuous-mastery families); S2/S4 have no separate "threshold" concept at all — mastery is the binary latent state itself.
- **Same threshold in both (S1/S3)?** Yes, by construction (one config field, no per-family override).
- **Measured before/after each response?** `truth(conceptId)` can be called at any point and always reflects the *current* state; `runTrackB.ts` calls it once before any response (`kStart`) and once after the session ends (`kT`/`kX`), and the per-step `truthByConcept` map returned by `respondAndLearn` captures it *after* that step's learning update (used for `itemsToCriterion`'s step-indexed lookup, Part 2).
- **Can a mastered concept become unmastered?** **No, in all four families** — S1/S3 are monotonically non-decreasing (fixed or growth-only `theta`), S2/S4 are explicitly "no forgetting" absorbing binary states. Mastery is an absorbing condition everywhere in this simulator suite.
- **How this feeds K(T)/QTM/censoring:** because mastery never regresses, `itemsToCriterion`'s "first step at which all T_c concepts are mastered" is well-defined and monotonic (once true, stays true for the rest of the session) — there is no possibility of a session "flickering" in and out of the attained state, which is what makes the simple first-crossing-step definition valid without needing a "stays mastered until the end" qualifier.
